This is an architecture option using tools available in 2024. The case study above describes the shipped product behavior.

- **Use the text layer when it is usable.** [PyMuPDF](https://pymupdf.readthedocs.io/en/latest/recipes-text.html) can return text blocks or words with coordinates. OCR is a fallback for scanned or unreadable pages. Parse each document version once and reuse its evidence across fields.
- **Use layout-aware extraction when structure carries meaning.** A table cell can lose its meaning when separated from its row and column headers. IBM's [August 2024 Docling report](https://research.ibm.com/publications/docling-technical-report) describes local layout and table recovery with optional OCR. [Amazon Textract Layout](https://aws.amazon.com/about-aws/whats-new/2023/09/amazon-textract-layout-feature-extract-paragraphs-titles-documents/) was already available as a managed option. [LayoutLMv3](https://arxiv.org/abs/2204.08387) was a document understanding model I would evaluate for specific layout or field-extraction tasks.
- **Measure cost per correctly cited field.** Test the same labeled documents across extraction routes. Track answer accuracy, citation accuracy, fields left for human review, and processing cost separately. Include representative scans, tables, and slide decks. Evaluate field accuracy and coverage together so the system gets credit for abstaining only when there is insufficient evidence.
